# Campus Secretary AI: ユーザー登録・認証フロー

## 方針

Taskieは「Discordファースト」の設計を採用する。

ユーザーはWebサイト上で事前登録を行う必要はない。サービス利用開始時の導線を極力短くし、

- サーバー参加
- Botとの会話開始

のみで利用を開始できることを目標とする。

## 初回利用フロー

### 1. Discordサーバー参加

ユーザーはTaskieのDiscordサーバーへ参加する。

### 2. Botへメッセージ送信

ユーザーがBotへメッセージを送信する。

例:

- こんにちは
- レポートがやばい
- 課題追加して

など任意の内容。

### 3. ユーザー自動登録

BotはDiscord User IDを取得し、ユーザー情報を自動生成する。

保持する情報:

- Discord User ID
- Discord Username
- Discord Avatar URL
- 登録日時

以後、このDiscord User IDをユーザー識別子として利用する。

### 4. 初回メッセージ

登録完了後、Botは歓迎メッセージを送信する。

例:

「初めまして。今日からあなたの秘書を担当します。」

この時点で課題管理・会話機能は利用可能となる。

## Webダッシュボード利用フロー

### 初回アクセス

ユーザーがダッシュボードへアクセスする。

例:

https://taskie.app/dashboard

未認証の場合はDiscord OAuth認証画面へリダイレクトする。

### Discord OAuth

取得情報:

- Discord User ID
- Username
- Avatar

OAuth完了後、Discord User IDを用いて既存ユーザーと紐付ける。

新規ユーザー作成は行わない。

ユーザー作成はDiscordでの初回会話時のみ実施する。

### ログイン後

ユーザーは以下の情報を閲覧できる。

- 今日の状況
- 未完了課題数
- 締切間近課題
- AIコメント
- AI日記
- 長期記憶一覧

## ユーザー識別

システム内ではDiscord User IDを唯一のユーザー識別子として利用する。

例:

discord_id = 123456789012345678

すべてのデータはこのIDに紐付く。

対象:

- タスク
- 会話履歴
- 長期記憶
- AI日記
- 設定情報

## 設計意図

Taskieは「まずAIと会話する」ことを最優先とする。

一般的なタスク管理アプリのような

- 会員登録
- メール認証
- 初期設定

を排除し、

「サーバー参加後すぐに話しかけられる」

体験を実現する。

ユーザー登録はシステム内部で自動的に行われ、ユーザーは登録作業を意識しない。

これにより、AI秘書との継続的な関係構築に集中できる。
